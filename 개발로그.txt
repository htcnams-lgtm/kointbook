[2026-09-30] ZZOINT 개발 로그 반영 1차 (수량·금액 콤마 / DB 색인)
■ 이번에 반영한 것
- 수량·금액 3자리 콤마 통일 (프로그램 전체)
  · 엑셀 저장: 제목에 수량/금액/판매가/단가/가격/합계/건수가 들어간 칸은 숫자로 저장 + #,##0 콤마 서식
    (공통 엑셀 저장 함수 4곳: ui_common.apply_amount_format). ISBN/바코드처럼 수량·금액이 아닌 칸은 그대로(앞자리 0 보존)
    - 이미 자체 콤마 서식이 있던 차이내역 상세, 재고현황 리포트는 그대로 둠
  · PC 화면 표: 실적관리 조사수량, 자료생성 조사수량, 이상치 확인 수량, SECTION 품목현황 수량,
    AREA 합산 건수/수량, PDA 수신 목록 수량, PDA 수신 작업자별 집계(건수/수량/계), 표본 등록 누락수량/건수
  · PC 안내창: 점포마스터/작업자마스터 PDA 전송 건수
  · PDA(Kotlin): 재고입력/재고수정의 ITEM 건수, 최대수량 초과 경고, 삭제 확인 문구의 수량 (총수량/SECTION 조회 등은 이미 콤마였음)
  · 수량 직접 입력칸은 숫자만 입력하는 칸이라 그대로 둠
- PC DB 색인 추가 (점포+조사일자+AREA/SECTION/서가/단/열, 점포+조사일자+ISBN): 실적관리/자료생성 등 화면 진입과 정렬 속도 개선.
  이미 있으면 건너뛰므로 기존 DB 그대로 사용 가능

[2026-09-30 2차] 가상 스크롤 / 팝업 정중앙 / 데이터 변경 감지 (속도는 기존보다 느려지지 않게)
■ 가상 스크롤 (새 파일 virtual_table.py)
- 표에는 화면에 보이는 줄(약 30줄)만 두고, 스크롤할 때 줄을 지우고 다시 만들지 않고 글자만 바꿈. 스크롤바는 전체 건수 길이.
  페이지 버튼(처음/이전/다음/끝)은 없어지고 스크롤(마우스 휠, 스크롤바 드래그, 방향키, PageUp/PageDown, Home/End) 하나로 통일
- 순서(id 목록)만 백그라운드에서 읽고(화면은 바로 뜸), 보이는 줄과 앞뒤 한 화면만 DB에서 읽어 잠시 기억. 총 건수/수량 합계는 SQL로 따로 계산
- 적용 화면
  · 실적관리 목록 + 조회 팝업: 조회 방식(전체/AREA/SECTION/AREA+SECTION/서가번호/바코드/도서명/작업자), AREA 합산전/후, 정렬(AREA, SECTION, 서가번호, 단, 열),
    체크/선택 헤더 전체선택/Space/더블클릭 수정/삭제/등록/수정은 예전과 같음. 체크·선택은 id 기준이라 화면 밖에 체크된 줄도 삭제 대상에 포함
  · 자료생성 실사내역 목록 (엑셀/자료 생성은 예전처럼 DB에서 읽음)
  · 상품마스터 목록 (예전의 3000건씩 이어서 채우기 → 가상 스크롤), 이상치 확인, SECTION 품목현황 (조회/필터 계산은 그대로, 보여주는 방식만 변경)
- 수정/삭제/등록 후에는 전체 재조회 없이 바뀐 줄만 반영 (등록은 정렬 위치를 다시 잡으려고 순서 목록만 백그라운드로 다시 읽음). 보던 위치/선택/체크 유지
- 화면 전환 시 다시 읽지 않음. 점포/조사일자/합산 기준이 그대로이고 실사 데이터도 안 바뀌었으면 그대로 사용.
  PDA 수신 저장, 실사자료 삭제(PDA수신/상품마스터 화면), 백업 복원 때만 다시 읽음 (db.stock_version). [조회] 버튼은 강제로 처음부터 다시 읽음
- 실적관리 엑셀저장: 표가 아니라 DB의 조회 조건 전체를 읽어 저장 (화면에 보이는 부분만이 아니라 전체). 행이 많으면 진행률 창
- 칸 복사(Ctrl+C): 스크롤한 뒤에도 클릭했던 칸 내용이 그대로 복사
- 시험(이 환경, 30만 건 가짜 데이터): 정렬된 순서 목록 읽기 약 1.2초(백그라운드), 스크롤 500회 약 0.4초, 수정/삭제/등록 반영과 정렬 순서가 SQL 결과와 일치
■ 팝업 정중앙 표시
- 실적 조회/수정/등록, 상품마스터 점포 선택, 점포/작업자마스터 등록, 샘플링 등록, 조사 Section 등록, 조사일자 선택 팝업을 프로그램 창 정중앙에 표시 (공용 함수 center_on_app)
■ 기타
- 예전부터 정의가 빠져 있던 _re_area 보완 (SECTION 범위 비교가 숫자로 동작하도록 - 이전에는 오류가 조용히 무시되고 글자 비교로 빠졌음)

■ 반영하지 않은 것 (이유)
- 차이내역 상세(screen_diff_detail): 소계 줄 아랫선(구분선)과 소계/합계 음영, 들여쓰기가 표 줄 위치에 묶여 있어서 표 방식을 바꾸면 모양/기능이 깨질 위험이 큼. 지금의 바코드 묶음 페이지 방식 그대로 유지
- 실적 [로케이션 수정]/[수정 취소]: KOINTBOOK의 위치 체계(AREA/SECTION/서가번호/단/열)가 달라 새로 설계해야 하는 기능이라 미반영 (필요하면 요청)
- 마스터양식(푸마/한화갤러리아), 갤러리아 업로드 생성, 장부 키 이어 붙이기, 영문 대/소문자 상품마스터 자동 매칭: 해당 없음 (도서/ISBN 기준 프로그램)
- PDA 실사 데이터 복원 전송(PC→PDA), 서버마스터 목록/이력, 조사일자 동기화(SURVEY.txt): KOINTBOOK에는 없는 기능이라 미반영
- PDA 화면 개편(재고수정 개편, 제목줄 31dp, 입력칸 36dp, 글씨 크기/굵기, 방향키 초록 테두리, 미전송/위치입력 화면 등):
  KOINTBOOK의 PDA 화면이 달라 확인 없이 옮기면 깨질 수 있어 미반영. 원하는 항목을 알려주시면 하나씩 맞춰서 반영

■ 이미 KOINTBOOK에 있던 것
- 실적관리 등록 팝업의 [등록완료] 안내 (엔터로도 동작)
- 마지막에 쓰던 점포/조사일자 DB 저장·복원 (app_settings)
- 미등록 경고 진동 권한

■ 확인 필요
- 이 개발 환경에는 tkinter 화면/안드로이드 빌드가 없어서 실제 화면과 앱 빌드는 확인하지 못했습니다.
  PC 프로그램은 파이썬 컴파일/이름 점검, DB 색인 생성, 가짜 화면으로 가상 스크롤 로직 시험까지 했고, 실제 화면은 PC에서 한 번씩 열어 확인이 필요합니다.
  엑셀 콤마 서식은 작은 표본으로만 확인했습니다. PDA(Kotlin)는 빌드하지 않았습니다.

[2026-10-01] PDA 화면 개편 대조 결과 (ZZOINT 로그 기준)
- 확인 결과, ZZOINT의 PDA 화면 개편 항목은 KOINTBOOK PDA에 이미 같은 요청으로 들어가 있어서 추가 수정이 필요 없었음 (코드/레이아웃 확인)
  · 재고수정 전면 개편(LOC 엔터 즉시 조회, 바코드 스캔 시 엔터 효과, 위치 칸 터치로 선택 V 표시, 목록 엔터→수량→엔터 수정, 방향키 초록 테두리)
  · 재고입력/재고수정 입력칸 높이·글씨 확대, 수동/자동 굵게, 상품명 칸 굵게, [재고수정] 버튼 방향키+엔터만 동작
  · 미등록 바코드 경고음 + 진동(KOINTBOOK은 더 짧은 120ms/볼륨 45/진동 200ms로 따로 설정되어 있어 그대로 둠)
  · 위치입력 화면 항목 검정·입력값 크게, 작업준비/DATA 관리/메뉴/초기화면 버튼 굵게·크기, 환경설정 시간 설정 삭제
  · DATA 조회/로케이션 조회 목록 글씨 확대·굵게, 간격 70%, 방향키 초록 테두리, 하단 버튼 크기·정렬, 전환 속도 개선(백그라운드 조회)
  · ITEM/총수량 천단위 콤마 (재고입력/재고수정/로케이션 조회/미전송 확인/무선전송)
- 상단 제목줄(모든 PDA 화면 공용 title_bar.xml): 화면 공간 활용을 위해 ZZOINT처럼 줄임 (높이 54dp -> 31dp, 막대 16dp -> 14dp, 글씨 17sp -> 14sp)
  · 한 파일을 모든 화면이 공유하므로 전체 화면에 적용됨. 늘어난 세로 공간은 목록 쪽에 쓰임
  · 재고수정 화면의 간격(LOC 줄 위아래 여백 4dp)은 이전 요청 그대로 둠
  · 앱 빌드는 하지 못했으므로 기기에서 확인 필요

[2026-10-01] 속도/렉 개선 (30만 건 가짜 데이터로 실측, 실제 화면 그리기 시간은 제외된 수치)
- 화면 전환: 보고서 화면(재고조사 보고서, AREA별 합산, 재고조사 차이명세, 섹션별 아이템 재고현황, 섹션별 결과보고서,
  샘플링 결과보고서, 이상치 체크 확인, Section Check 화면)은 들어올 때마다 다시 계산했음(차이명세 약 2.4초, 재고조사 보고서 약 0.8초 등).
  점포/조사일자가 같고 DB가 바뀌지 않았으면 다시 계산하지 않고 그려진 화면을 그대로 보여줌 (db.data_version).
