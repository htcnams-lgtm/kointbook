# KOINTBOOK 재고실사 관리 시스템

RBSKOREA가 KYOBO(교보문고) 매장에서 진행하는 도서 재고실사 화면들(캡처 15장)과,
그 화면들이 어떤 "프로세스"로 이어져 있는지를 보여주는 기존 ZZOINT(일반 매장용
데모) 소스코드를 함께 참고해서 새로 만든 프로그램입니다.

캡처 화면들이 일부 잘려 있거나(헤더 일부만 보임) 특정 버튼을 눌렀을 때의 동작까지는
보이지 않는 경우가 많아서, "헤더에 있는 항목명"과 "ZZOINT가 이미 구현해둔 비슷한
기능의 처리 방식"을 근거로 기능을 유추해서 채워 넣었습니다. 아래 문서 뒷부분의
**"추측/가정한 부분"**을 꼭 한번 확인해서, 실제 RBSKOREA-KYOBO 프로그램과 다르게
동작해야 하는 부분이 있으면 알려주세요. 코드 구조상 대부분 한두 줄만 고치면
됩니다.

## 0-2. [2026-09-23 재재재정정] 위치입력화면 입력 보강 + 앱 아이콘 예시

  그대로 씁니다.
- **자릿수를 "정확히" 맞아야만 확정되게** 강화했습니다 - 이전에는
  `maxLength`로 "그 이상 입력을 막는" 것만 했어서 1자리만 입력해도 다음

### 1-1. exe로 만들기 (PyInstaller)

[2026-09-28] "ZZOINT는 EXE 파일 하나로 모두 실행되게 platform-tools도
포함되는데? exe파일하나로 다되게 만들어줘" - ZZOINT와 똑같이 **exe 파일
하나**로 실행되도록(--onefile) `pc_app/KOINTBOOK.spec` 빌드 설정 파일을
만들어뒀습니다. `assets`(로고/아이콘)와 `platform-tools`(adb) 폴더도 이
exe 안에 그대로 같이 담깁니다. 또 [발행] 버튼의 인쇄 미리보기(pywin32)
기능까지 exe에서 그대로 동작하도록, PyInstaller가 자동으로 못 찾는
pywin32 내부 모듈(`win32timezone` 등)도 이 스펙 파일이 명시적으로 포함시켜
둡니다(그냥 `pyinstaller KOINTBOOK_pc.py`로 직접 빌드하면 이 부분이 빠져서
exe에서만 인쇄 미리보기가 안 뜨는 문제가 생길 수 있습니다).

Windows PC(프로그램을 실제로 돌리는 그 PC, 엑셀이 설치돼 있어야 함)에서:

```
cd KOINTBOOK\pc_app
pip install openpyxl pywin32 pyinstaller
pyinstaller KOINTBOOK.spec
```

빌드가 끝나면 `pc_app\dist\KOINTBOOK_pc.exe` **파일 하나**만 생깁니다 -
이 파일 하나만 옮겨서 실행하면 됩니다(`assets`/`platform-tools`도 이미
exe 안에 들어있어서 따로 같이 옮길 필요가 없습니다).

- **주의**: `pip install pywin32`는 exe를 만드는 이 빌드 PC에서만 하면
  되고, 실제로 프로그램을 사용하는 매장 PC에는 따로 설치할 필요가
  없습니다(pywin32가 필요로 하는 부분은 이미 exe 안에 포함돼서 나갑니다).
  다만 **엑셀(Microsoft Excel) 자체는 그 매장 PC에 설치돼 있어야** 인쇄
  미리보기 기능이 동작합니다(엑셀이 없으면 exe는 정상 실행되지만,
  [발행]을 눌렀을 때 미리보기 없이 조용히 기본 프린터로 인쇄하는 방식으로
  자동 대체됩니다).
- 빌드에 쓰는 파이썬 환경에 `pywin32`가 설치돼 있지 않으면
  `pyinstaller KOINTBOOK.spec` 실행 중 `win32com` 관련 모듈을 못 찾는다는
  오류로 빌드 자체가 실패합니다 - 위 명령처럼 빌드 전에 반드시 먼저
  설치하세요.
- exe 파일 하나로 실행되는 방식(`--onefile`)은 실행할 때마다 안에 담긴
  파일들을 임시 폴더에 풀었다가 쓰는 구조라(PyInstaller의 `_MEI` 폴더),
  첫 실행이 몇 초 정도 더 걸릴 수 있습니다 - `base_dir.py`/`adb_utils.py`가
  이미 이 상황을 감안해서 실행 파일(exe) 기준 폴더를 올바르게 찾도록
  만들어져 있습니다.

구분). 각각 ISBN/도서명/분야명/출판사/전산재고/실재고/누락재고/예외여부에
대응됩니다. **가장 중요한 발견**: 전산재고·실재고·누락재고·예외여부는
KOINTBOOK이 계산해서 만드는 값이 아니라 이 파일 자체에 이미 들어있는
값이었습니다(예: 실재고가 항상 "이번 조사에서 스캔한 수량"인 게 아니라
마스터 쪽 기준값입니다). 그래서 `books` 테이블에 `rcds_qty`/`real_qty`/
`missing_qty`/`except_flag` 4개 컬럼을 추가해 그대로 저장하고, 상품마스터
화면은 이제 이 값을 계산 없이 그대로 보여줍니다. CSV/엑셀 둘 다 "파일선택
변환"으로 불러올 수 있습니다.

**② 자료생성 버튼 ↔ 실제 결과 파일 매칭**:

| 버튼 | 실제 결과 파일(샘플) | 형식 |
|---|---|---|
| 자료①,②생성 | `kyobo_data1.txt` + `kyobo_data2.txt` | 헤더/구분자 없는 고정폭 텍스트(EDI 피드용으로 보입니다). ①=ISBN(13)+수량(6, 0채움)=19자리, ISBN별 전체 스캔수량 집계. ②=서가번호+ISBN(13), 스캔된 (위치,ISBN) 조합마다 한 줄(수량 없음) - 받은 샘플에서는 서가번호가 11자리(전체 24자리)였지만 서가번호 자체가 점포별 임의 배정값이라 항상 그 자릿수가 고정된다는 보장은 없습니다 |
| ③ 단품 리스트생성 | `{점포}_결과확인리스트(날짜).xlsx` | 상품마스터 **전체 품목**(스캔 여부 상관없이) + 스캔재고/차이 비교표. 컬럼: ISBN,도서명,분야,출판사,전산재고,실재고,누락재고,예외여부,스캔재고,차이(=스캔재고-전산재고) |
| ④ 서가별 생성 | `{점포}_서가별스캔데이터(날짜).xlsx` | 스캔 **1건당 1행**(집계 안 함). 컬럼: ISBN,도서명,분야,출판사,서가번호,실사수량 |
| ④-2 서가별 합산 | `{점포}_서가별스캔데이터(서가별합산)(날짜).xlsx` | ④와 같은 컬럼인데 같은 바코드 + 같은 서가번호는 한 줄로 합산(합계 0은 제외, 바코드 -> 서가번호 순) |
| 자료생성(미등록) | (샘플 없음, 기존 추정 유지) | 상품마스터에 없는 ISBN만 모은 리스트 |
| 합산자료(AREA) | (샘플 없음, 기존 추정 유지) | AREA별 건수/수량 합계 |

파일명의 "{점포}"는 실제 샘플이 점포명 끝 "점"을 뗀 형태("인천점"→"인천")를
썼길래 그렇게 맞췄습니다(`ui_common.short_store_label`).

**[2026-09-23 현장 확인] "서가번호"는 정해진 자릿수 공식이 없습니다** —
점포에서 구역(AREA/SECTION)별로 임의로 매겨놓은 번호일 뿐이라, "점포코드3+
AREA2+SECTION2+서가번호2+단1+열1=11자리"처럼 자릿수 통계로 유추했던 이전
버전의 공식은 틀린 접근이었습니다. 확인된 규칙은 **AREA가 항상 숫자
2자리(01, 02, 11, 12...)이고 알파벳이 섞이지 않는다**는 것뿐입니다. 그래서
`generation.location_code`는 이제 AREA만 2자리로 맞추고 나머지(SECTION/
서가번호/단/열)는 입력된 값을 그대로 이어붙입니다(자리수를 임의로 자르거나
늘리지 않음 - 잘라내면 실제 배정된 번호가 훼손될 수 있기 때문). KOINTBOOK
DB에는 이 "서가번호" 원본 코드 자체를 저장하는 필드가 없어서(PDA/매대등록
에서 AREA/SECTION/서가번호/단/열로 이미 나눠 받습니다) 이어붙인 값이
RBSKOREA가 실제로 쓰는 서가번호와 자릿수까지 완전히 같다는 보장은 없습니다.
RBSKOREA에서 원본 서가번호 값을 그대로 내려주거나 매대등록 화면에서 직접
입력받을 수 있게 되면, 계산 대신 그 값을 그대로 쓰는 것이 가장 정확합니다.

## 6. 추측/가정한 부분 (캡처가 잘려서 확인이 필요한 항목)

캡처만으로는 정확한 계산식이나 버튼 동작까지 100% 확신할 수 없어서, 아래는 제가
"가장 그럴듯하다"고 판단해 정한 규칙들입니다. 실제 RBSKOREA-KYOBO 프로그램과
다르면 알려주세요 — 대부분 함수 하나만 고치면 되는 구조입니다.

1. **AREA 합산전/후**: [2026-09-23 정정] 처음에는 "1A", "1B" 처럼 AREA 뒤에
   영문 접미사가 붙어 "합산후"를 선택하면 그 접미사를 떼서 "1"로 합쳐
   집계한다고 가정했는데, 실제로는 AREA가 항상 숫자 2자리(01, 02, 11,
   12...)이고 알파벳이 섞이지 않는다는 것이 확인되어 그 가정이 틀렸습니다.
   그래서 `ui_common.normalize_area`는 이제 알파벳을 떼는 처리 없이 숫자만
   2자리로 맞추기만 하고, 결과적으로 "합산전"/"합산후" 두 선택이 같은 값을
   보여줍니다. 화면의 라디오 버튼 자체는 일단 그대로 남겨뒀지만, 실제로
   AREA를 다른 기준으로 묶어서 봐야 하는 경우(예: 여러 조가 SECTION을
   나눠 맡는 방식이라면)가 있다면 알려주시면 그 기준으로 다시 고치겠습니다.
1-1. **서가번호 자릿수 구성**: [2026-09-23 정정] 3-1절에서 설명한 대로, 점포
   에서 구역별로 임의로 매겨놓은 번호일 뿐 정해진 자릿수 공식이 없다는
   것이 확인되어, `generation.location_code`는 더 이상 자릿수를 추정해서
   계산하지 않고 AREA(2자리 숫자)만 고정 규칙으로 두고 나머지는 입력값을
   그대로 이어붙입니다. 이어붙인 값이 RBSKOREA 쪽 원본 서가번호와 자릿수
   까지 똑같다는 보장은 없으니, 원본 값을 그대로 받을 방법이 있으면
   알려주세요.
2. **Section Check의 "조사완료/중복/결번/추가" 정의**:
   - 조사완료 = 계획(`planned_sections`)한 Section 중 실제 수신된 것
   - 중복 = 같은 Section을 2명 이상의 작업자가 실사한 경우 (아직 "중복 인지"
     처리를 안 한 것만 표시)
   - 결번 = 계획했지만 실사 데이터가 하나도 없는 Section
   - 추가 = 계획에 없었는데 실사 데이터가 들어온 Section (진행현황 화면에서 표시)
3. **재고조사 진행 현황의 5개 박스**: 총섹션=계획∪실제, 완료섹션=계획∩실제,
   미완료섹션=계획-실제, 중복섹션=위 2번 정의, 추가섹션=실제-계획. 진행률(%) =
   완료섹션 ÷ 총섹션 × 100.
4. **샘플링 결과보고서의 책임 소재 분류**: 미스유형 중 "카운터누락/입력미스/
   카운터미스/스캔미스/혼합카운터"는 RBSKOREA(실사 대행사) 책임, "사전정리미스/
   진열정보미스"는 KYOBO(매장) 책임으로 나눴습니다. 미스율은 RBSKOREA측 미스만
   분자로 계산합니다.
5. **재고조사 차이명세의 집계 단위**: 위치(로케이션)별 행을 그대로 보여주면서,
   전산재고/실재고/누락수량은 ISBN 기준 매장 전체 값을 각 행에 함께 표시하는
   방식으로 만들었습니다. "차이수량(±)" 입력값이 있으면 그 값 이상 차이나는
   행만 필터링합니다.
6. **섹션별 결과보고서의 3단 인쇄 레이아웃**: Section을 정렬한 뒤 1/3씩 3열로
   나눠 보여주도록 만들었습니다(인쇄용 캡처의 "가로로 3구획 반복되는" 배치를
   재현).
7. **상품마스터 "예외" 처리**: 행을 더블클릭하면 해당 ISBN을 조사 대상에서 제외
   (또는 제외 해제)하는 토글로 구현했습니다. 예외 지정된 품목은 누락수량 계산
   등에서 제외하지는 않고 "예외여부" 컬럼에만 표시해 둡니다(집계 제외 여부는
   캡처로 확정하기 어려워, 우선 표시만 하도록 보수적으로 처리).
8. **PDA Data 수신의 "임시→확정" 2단계 구조**: 수신 즉시 `stock_counts`에 바로
   쌓지 않고, 화면에서 한 번 확인한 뒤 [저장] 버튼을 눌러야 확정 저장되도록
   만들었습니다(중복수신/오수신을 사전에 걸러낼 수 있게).

## 8. 안드로이드(PDA) 앱 — `android_app`

ZZOINT의 `android_app`(패키지 `com.example.usbbridge`, Kotlin + Firebase)을
기반으로, KOINTBOOK PC 프로그램의 스키마(ISBN, AREA/SECTION/서가번호/단/열)에
맞춰 화면과 로컬 DB(`KOINTBOOK.db`)를 다시 짰습니다.

**빌드 방법**: Android Studio에서 `android_app` 폴더를 열면 됩니다
(`minSdk 21`, Kotlin). **패키지명(applicationId)은 `com.kointbook.app`
입니다** ([0-10절](#0-10-2026-09-24-pda-앱-패키지명applicationid-분리)
참고 - ZZOINT(`com.example.usbbridge`)와 다른 값이라 같은 PDA 기기에
ZZOINT 앱과 KOINTBOOK 앱을 같이 설치할 수 있습니다). 이 값은 PC 쪽
`adb_utils.py`의 `PACKAGE_NAME`과 반드시 똑같아야 합니다(다르면 adb가
PDA 앱의 파일 폴더를 못 찾습니다). Kotlin 소스 파일들의 `package` 선언과
`namespace`(빌드 설정)는 `com.example.usbbridge`로 그대로 뒀습니다 -
`applicationId`(설치 식별자)와 `namespace`/`package`(코드 내부 이름)는
안드로이드에서 서로 별개라서, 소스 파일을 옮기지 않고 이 값만 바꿔도
됩니다.

**화면 흐름**: 스플래시 → 작업준비(점포/작업자 확인, 마스터 수신) → 메뉴
(Data 입력/Data 관리) → 위치입력 → 재고입력(스캔 화면) 순으로, ZZOINT와
거의 동일합니다. 다음 부분이 바뀌었습니다.

1. **위치 입력화면은 AREA/SECTION/서가번호 세로 3칸**: ZZOINT는 "로케이션"
   1개 값만 입력받았지만, KOINTBOOK은 캡처 화면대로 위치입력화면을 세로로
   3칸(1.AREA 2.SECTION 3.서가번호)으로 나눴습니다([2026-09-23 정정] - 예전엔
   "1-5-12"처럼 하이픈으로 이어붙인 문자열 하나를 입력받아 3개로 쪼개는
   방식이었는데, 실제 작업 흐름과 안 맞아 3칸으로 나눴습니다). 각 칸은
   독립적으로 동작합니다 - 물리 스캔버튼으로 찍으면 지금 포커스가 있는
   칸에 그 값이 들어가고, 직접 타이핑한 뒤 엔터(또는 키보드의 "다음")를
   눌러도 마찬가지로 다음 칸(AREA→SECTION→서가번호)으로 자동 이동합니다.
   마지막 칸(서가번호)에서 확정하면 재고입력화면으로 넘어갑니다.
   [2026-09-23 재정정] 각 칸에 자릿수 제한을 걸었습니다 - **AREA 2자리,
   SECTION 3자리, 서가번호 11자리**(서가번호는 PC/PDA 공통으로 11자리입니다).
